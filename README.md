# 关系决策牌组 V0.9

围绕持续沟通设计的纯前端卡牌原型：对方打出场景牌，用户从手牌中选择表达方式，并把有价值的交锋收藏到卡包。

## 技术边界

- 原生 HTML、CSS、JavaScript，不依赖前端框架或外部 CDN；
- 没有账号、数据库和业务后端，构建产物可直接部署到静态服务器；
- 试玩状态自动保存在浏览器 `localStorage`；
- 支持导出、导入单个 JSON 文件，备份人物、项目、关联关系、回合和卡包；
- 已提供 OpenAI 兼容 API 的配置与客户端，当前发牌仍保留原型数据，后续可以逐步替换为真实 AI；
- 浏览器直连 API 会暴露密钥，只适合本机或可信局域网试玩；公开部署时应增加轻量服务端代理。

```text

```

## 本地运行

```bash
./serve.sh
```

访问 <http://127.0.0.1:4111>。局域网移动端可使用电脑的局域网 IP 和 `4111` 端口访问。

## 测试与构建

仅需 Node.js 20 或更高版本，不需要安装第三方依赖。

```bash
npm test
npm run build
npm run check
```

`npm run check` 会执行数据模型、存储迁移、AI 客户端、UI 契约和静态构建测试。部署时上传整个 `dist/` 即可。

## V0.9 能力

- 首页聚焦“对方出牌 → 当前交锋 → 我的手牌”，移动端把对方场景入口压缩为按钮；
- 当前双方卡牌均可点击查看完整内容，卡面用分区、引语和结论强化信息层级；
- 对方牌堆、当前牌、手牌和收藏卡复用同一套蓝金卡牌语言；
- 人物详情和项目详情保持独立，但合并零散字段并支持直接编辑；
- 项目阶段可下拉修改，人物和项目通过 `person_matter_links` 建立多对多关系；
- V1 浏览器数据会自动迁移到 V2，旧人物—项目关系不会丢失；
- AI 设置支持 Base URL、模型、API Key、模型列表连通性测试和可选本机记忆密钥；
- 默认导出文件不包含 API Key；如需跨设备使用 AI，应在目标设备重新填写密钥。

## 数据模型

人物和项目各自只保存自身资料，关联关系单独存放：

```json
{
  "person_matter_links": [
    {
      "person_id": "person-1",
      "matter_id": "matter-1",
      "role": "决策人"
    }
  ]
}
```

这样同一个人可以参与多个项目，同一个项目也可以关联多个人；每个人至少保留一个项目，以保证牌桌始终存在有效上下文。

## AI 配置边界

客户端使用 OpenAI 兼容的 `/v1/models` 和 `/v1/chat/completions` 接口，并通过 `Authorization: Bearer` 发送密钥。第三方服务只要兼容这些路径与响应结构，即可填写自己的 Base URL。

当前版本只完成配置、连接测试和通用对话客户端，没有把每个“模拟 AI”按钮都改成真实调用。这能先固定原型交互，也避免在牌面与提示词尚未稳定时过早绑定模型。

## 原型限制

- 发牌、判断和模拟建议目前仍以本地规则及演示数据为主；
- `localStorage` 只属于当前浏览器，跨设备需要手动导出和导入；
- 数据文件包含用户录入的事实、回合和卡包内容，应由用户自行保管；
- 未实现多人共享、账号同步和现实结果分析；
- 模拟内容不代表现实预测。
